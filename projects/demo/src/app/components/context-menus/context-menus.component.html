Custom Context Menus Both dashboard context menus, rendered by this page instead of the library

Right-click a widget and CELL_CONTEXT_PROVIDER is asked first. The library hands over the entries it would have shown - Edit Widget, Edit Shared State where the widget has one, Settings, Delete - each carrying the action that performs it, and this page renders them in its own menu. Returning true is what stops the library from drawing anything; returning false would fall back to its menu.

Right-click an empty cell and EMPTY_CELL_CONTEXT_PROVIDER is asked instead. That hook hands over no entries - there is no widget to act on - so the page composes its own from the registered widget types and creates the chosen one through the context's createWidget callback. The type added last is repeated at the top: quick-repeat state the page owns, not the library.

Both menus are the page's own component, so both carry its outline and name the context they were handed - CellContext or EmptyCellContext - as their heading. "Custom alert" is an entry the library never built, spliced in ahead of the divider that fences off Delete: the entries are data, so the page adds, drops, reorders and regroups them - dividers included.

Neither menu fires outside edit mode. Turn editing off and the browser's own menu comes back.
